# Исследовательский экран Waveshare S3 LCD7

Профиль `s3_lcd7`: Waveshare ESP32-S3-Touch-LCD-7 Rev1.2, 800×480,
16 MiB flash, octal PSRAM, RGB565 и GT911. Это экран основной Bluetooth-демки,
а не отдельный владелец Bluetooth. C6 и обычный профиль `s3` не подключают
этот компонент и его LVGL-зависимости.

## Рабочий обзор

- **Air**: компания первой колонкой, имя/распознанный тип, адрес, RSSI,
  число пакетов и возраст. Зелёное имя означает наличие распознавателя.
  Выбор строки открывает справа полные названия AD-полей, hex и raw-пакет.
  Можно выбрать обработчик из списка и явно добавить экземпляр.
- **Devices**: BT-owned экземпляры с поколением ID. Справа — доступные
  команды модуля, их состояние, события и последнее сообщение CBOR.
  Удаление и команды идут через ту же очередь, что использует вебка.
- **CBOR**: ограниченный журнал произвольных измерений/событий. Декодер
  показывает имена полей и вложенные значения, не знает HRM/TPMS/SmartTag.
  Текст ограничен 2048 байтами, 96 значениями и глубиной 4; большие строки
  помечаются, исходный payload не изменяется. Полный просмотр остаётся в вебке.

Верхняя строка отражает состояние backend и счётчики. Pause/Start запрашивают
изменение, подпись обновляется по подтверждённому состоянию движка. Ответ
`Engine: ok` означает принятие команды движком/драйвером, а не обязательно
завершение GATT-операции. Внизу — реальный IP либо offline, SIG и потери.
Таблица и виджеты создаются один раз; обновляются изменённые значения.

Все LVGL вызовы, чтение ResearchModule/MessageJournal и обработка команд
сериализованы в задаче приложения. GAP callbacks LVGL не вызывают. Отдельный
стек, callback Bluetooth, поиск приборов по RSSI и дублирование экземпляров
в экранном коде не создаются.

На S3 после прошивки проверена совместная работа BLE + Wi-Fi + RGB: эфир
поступает, HTTP assets и бинарный WS/CBOR доступны, Pause/Start и восстановление
снимка после разрыва работают. RGB кадры обновляются; GT911 определяется и
опрашивается без ошибок. Визуальный вид физической панели и касание пальцем
этой удалённой проверкой не подтверждаются.

## Сборка без прошивки

Из корня NaBTools:

```powershell
pio run -d examples/research -e c6
pio run -d examples/research -e s3_lcd7
```

Второй профиль сохраняет прежнюю таблицу разделов демки: NVS/PHY и приложение
по прежним смещениям. Он не включает provisioning или команды прошивки.
На плате с другой установленной разметкой нельзя считать его автоматически
совместимым; её проверяют отдельно перед разрешённой загрузкой.

## Проверка на компьютере

После разрешения managed dependencies S3:

```powershell
cmake -S examples/research/tests/lcd7 -B local/research-lcd7-host
cmake --build local/research-lcd7-host --config Debug
ctest --test-dir local/research-lcd7-host -C Debug --output-on-failure
```

Для другого расположения исходников задаются `LVGL_SOURCE_DIR` (LVGL 9.6.0)
и `TINYCBOR_SOURCE_DIR`. Тест использует настоящий LVGL, проверяет выбор,
очередь add/scan/remove, generic CBOR и усечённые payload; создаёт PPM-снимки
800×480 в build-каталоге. Все приборы и данные в этих снимках синтетические.
Это не эмуляция RGB-периферии и не физическая проверка GT911.
Надписи используют Montserrat 14; произвольные национальные символы имён
могут требовать дополнительного шрифта с соответствующими глифами.

## Происхождение

`board.cpp` и `board.hpp` адаптированы из публичного примера
`NaCBORUIforLVGL/examples/s3_style_lab/main/board.*`, который в свою очередь
сохраняет происхождение RGB-драйвера из NaWServer/ESP32-yaidfws touch_lcd7.
Адаптации `board.cpp`/`board.hpp` сохраняют GPL-3.0-only и текст в `LICENSE`;
остальной самостоятельно написанный экранный код — MIT по корневому LICENSE.
Итоговый пример с GPL-адаптером не объявляется полностью MIT.
Старый BLE/LVGL архив не восстанавливался.
GPIO, тайминги, владение двумя framebuffer и ожидание frame/VSYNC сохранены.
Для совместной работы RGB + BLE + Wi-Fi два внутренних bounce-буфера уменьшены
с 16 до 8 строк. Статические RX/TX буферы Wi-Fi ограничены четырьмя каждый,
RX Block Ack window — четырьмя; dynamic RX — 16 и TX cache — 8.
Это параметры приложения для данного экрана, а не ограничения BtEngine.
Динамические данные Bluedroid размещаются сначала в PSRAM; включено динамическое
выделение BLE-окружения. Задачи Bluetooth и DMA-буферы остаются во внутренней памяти.
UART0 служит основной диагностической консолью, USB Serial/JTAG — дополнительной.
Раз в пять секунд журнал выводит кадры LCD, готовность GT911, ошибки touch
и свободную внутреннюю память. Это не заменяет визуальный осмотр панели.
Другие репозитории при этой работе не изменялись.
