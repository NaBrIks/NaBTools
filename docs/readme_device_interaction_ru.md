# Команды, события и активная работа с приборами

Уточнение владельца 23.10.2026: общая страница экземпляров должна уметь
показывать события и выполнять команды, объявленные обработчиком. Знание
конкретного протокола остаётся в модуле, общий механизм не привязан к SmartTag
или к ESP32. Направление принято; весь активный BLE стек этим ещё не реализован.

## Границы

- `BtEngine`: владение экземплярами, проверка DeviceId/generation, сериализация
  вызовов. Опциональный backend соединений/GATT инкапсулирует аппаратный SDK;
  [реализация и аппаратная проверка](readme_gatt_ru.md).
- Модуль прибора: узнавание, идентичность, протокол, аутентификация, смысл событий
  и перевод команд в операции прибора. Например, SmartTag и HRM имеют разные
  протоколы, но пользуются общими механизмами.
- Приложение: состав получателей Actions и реакция на события, транспорт,
  конфигурация и хранение. Вебка — один из таких потребителей.
- Общая вебка: выводит каталог и данные; не содержит веток Samsung/TPMS.

Пассивное наблюдение, добавленный экземпляр, установленное BLE соединение,
BLE pairing/bonding и регистрация владельца — разные состояния/операции.
Кнопка «Добавить» в исследователе по-прежнему не передаёт ничего метке.

## Реализованный первый механизм

`include/NaBTools/bt/interaction.hpp` содержит заимствованные `InteractionInfo`,
`OperationInfo` и `DeviceCommand`. Экземпляр необязательно предоставляет
каталоги `commands` и `events`: ключ, подпись, текущая доступность и причина.
Пустой каталог — нормальный вариант для прежних пассивных драйверов.

```cpp
InteractionInfo IDevice::interaction() const;
Status IDevice::invoke(BtEngine&, DeviceId, const DeviceCommand&);
Status BtEngine::invoke(DeviceId, const DeviceCommand&);
```

`DeviceCommand` содержит ключ, формат аргументов, borrowed bytes, request_id
и время. Движок не декодирует аргументы и не требует CBOR. Необязательный
wire adapter модуля проверяет формат и вызывает типизированный API драйвера.
Такой вызов из обычного прикладного кода может вообще обходиться без wire adapter.
Нет обязательного общего DOM или промежуточной структуры данных прибора.

Вызовы проходят только в контексте движка. Неизвестные/недоступные команды
отвергаются до вызова драйвера. Старый ID после удаления не управляет новым
экземпляром в том же слоте. Удаление из callback откладывает деструктор до
возврата из команды; рекурсивные invoke/poll дают busy.

Защищённый `BtEngine::dispatch(DeviceId, context, handler)` даёт тот же срок
жизни для borrowed входов необязательных адаптеров, без знания GATT/CBOR.
Первый потребитель — HeartRateDevice::on_measurement. Это не асинхронная очередь:
передачу SDK callback в контекст движка по-прежнему обеспечивает backend/адаптер.

`ok` для invoke означает принятие драйвером, а не подтверждение выполнения
на радиоканале. Результат реальной операции и события идут через Actions
драйвера. Его асинхронная реализация должна владеть сохранёнными аргументами,
отменять свои операции/подписки при удалении и проверять generation при
доставке поздних результатов. Эти операции и завершения теперь описаны
переносимым IGattClient; ограничения ESP-IDF приведены в документе GATT.

Типизированные callbacks и прямой CBOR остаются независимыми выходами.
Каталог событий описывает возможности; наличие записи в нём не означает,
что событие было получено. Существующий журнал принимает произвольные CBOR
сообщения через Actions. Отдельного редактора правил автоматизации в вебке нет.

## Исследовательский WS/UI адаптер

Слева расположена таблица экземпляров, справа — его MAC/ID, объявленные команды,
события и generic CBOR viewer. Недоступная команда выключена; причина в подсказке.
Текущая форма запускает команды без параметров с пустой CBOR map.

Все данные, команды и результаты идут через [единый WS/CBOR поток](readme_websocket_ru.md).
`queued` означает принятие в очередь, control — результат dispatch, сообщение
драйвера — дальнейшее состояние протокола. Boot ID и поколения защищают поздние
команды. Автоматических повторов команд нет.

Описания модуля включаются отдельно от SIG и формата outputs.
SmartTag button/ring требуют успешной owner-аутентификации. Экспериментальная
реализация и источник ключа описаны в [owner-протоколе](readme_smarttag_owner_ru.md).
На EI-T5300 подтверждены взаимная аутентификация и запуск звука; реальные
события кнопки и надёжный Stop sound ещё проверяются.
Исследовательские discovery/info/raw-подписка описаны
[отдельно](readme_smarttag_gatt_ru.md). Общий GATT транспорт этих функций не подменяет.

## Следующий активный слой

Переносимый API connect/discovery/read/write/subscribe/cancel и ESP-IDF адаптер
с owned callback очередями реализованы: [GATT](readme_gatt_ru.md). Далее нужны
устойчивое сопоставление экземпляра с текущим адресом и протоколы аутентификации. Универсальность здесь
означает общие механизмы и границы, а не отсутствие специальных драйверов.

У SmartTag есть постоянная идентичность и секреты, но в рекламе меняются MAC
и privacy ID. Пассивно объединять адреса по RSSI нельзя. BLE pairing не равен
регистрации Samsung или разрешению owner-команд; метка тоже участвует
в аутентификации. Текущий модуль реализует owner-протокол для EI-T5300;
доступность команды после ATT ACK не заменяет аппаратную проверку её результата.

Источники: [протокол SmartTag, USENIX 2024](https://www.usenix.org/system/files/usenixsecurity24-yu-tingfeng.pdf),
[Samsung: Ring и действия кнопки](https://www.samsung.com/us/support/answer/ANS10005275/),
[Samsung: автоматизация требует соединения метки с телефоном](https://www.samsungsvc.co.kr/solution/42456).
Исследование описывает определённые версии прошивок; совместимость каждой
модели и версии требует отдельной аппаратной проверки.

## Проверка

На первом этапе прошли 13/13 native C++ тестов и 7/7 Node проверок; после
добавления Heart Rate и переноса папок — 16/16 и 8/8. Тест interaction
не линкует CBOR и аппаратный SDK: проверяет dispatch/Action, отказ в неизвестной
команде, доступность, валидацию формата модулем, удаление из callback,
отсроченное уничтожение и защиту старого ID. Парсер команд дополнен проверкой
invoke и всех его усечений. Это проверка механизма, а не аппаратная приёмка GATT.

В эфирной таблице компания первая; все восемь заголовков переключают ascending/
descending, показывают направление, доступны с клавиатуры. RSSI/счётчики/возраст
сортируются как числа. Выбор сохраняется в localStorage и применяется при
обновлении, фильтрации и смене языка.

Актуальный транспорт и его проверки описаны в [WS/CBOR](readme_websocket_ru.md).
