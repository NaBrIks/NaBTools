# Исторические ограничения удалённой реализации

Ниже сохранены результаты чтения исходной библиотеки 23.10.2026. Код, к которому
относятся `DeviceData`, `getManufacturerId`, weak CBOR loop и авторегистрация,
удалён 29.10.2026. Этот перечень не является списком дефектов текущего runtime.
Текущие возможности, проверки и ограничения: [аудит переноса](readme_retired_code_ru.md).

1. Исправлено 23.10.2026 при обновлении SIG: lookup больше не ожидает
   отсутствующий sentinel, а проходит конечный массив. Шаблон и производные
   обновлены вместе; известный/неизвестный/верхний код проверены native тестом.
2. `getManufacturerId()` читает два байта без проверки `size() >= 2`.
3. `DeviceData::id[16]` недостаточен для 17 символов MAC плюс `\0`.
   TPMS не гарантирует терминатор, SmartTag теряет часть адреса.
4. `DeviceData::id`, часть `TPMSData` и `warning` не инициализируются общим
   конструктором. Тестовый распознаватель отправляет частичную структуру.
5. AD хранится по одному элементу на type; повторные блоки перезаписываются.
   Разбор не возвращает явную ошибку повреждения/неполноты и не собирает extended
   advertising fragments. Внешний lvgl-cbor scanner ограничивает допустимые входы.
6. Controller принимает report по значению, копируя map со span, но не владея
   байтами; перенос такого объекта в асинхронную очередь небезопасен.
7. Первый совпавший recognizer исключает остальные. Разбор повторяется для Log
   и SendEvent; JSON/CBOR, подробные логи и ожидание до 3000 ms работают на пути
   GAP callback. В SmartTag возможны две последовательные отправки с ожиданием.
8. Авторегистрация скрыто создаёт singleton/event loop со стеком/очередью и
   привязкой к ядру. Нет явного протокола unregister/stop и владения модулями.
9. Карта известных устройств не заполняется через публичный API; `WithAddress`
   не образует готовый жизненный цикл. SmartTag-метод объявлен без реализации.
10. TPMS signed temperature, трактовка SmartTag и идентичность по MAC нуждаются
    в подтверждении эталонными пакетами/источниками.
11. Сохранены тестовый MAC-recognizer, weak `CBOR_loop`/`CBOR_EVENT`, пробный
    PMR-вывод и функция `d()`, из-за которой нужен C++23. Их следует модульно
    отделить, сохранив исследовательские возможности.
12. Некоторые include используют Windows `\`; самостоятельные заголовки и
    стандартные includes требуют проверки на другом компиляторе/ОС.

Рекомендуемые первые проверки: неизвестные SIG-коды, нулевые/короткие/битые
AD, повторные service data, пустые значения, полная строка адреса, отрицательная
температура, перенос владения и переполнение очереди. Компиляция этих свойств
не доказывает.
