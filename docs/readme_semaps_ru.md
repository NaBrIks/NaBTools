# Архитектурная документация SeMaps

Открыть `NaBTools.semaps` установленным SeMaps или из корня репозитория:

```sh
semaps NaBTools.semaps
semaps check NaBTools.semaps
```

Модель `nabtools` находится в `docs/diagrams/projects/nabtools`.
Это авторская карта ответственности по текущим исходникам, а не автоматически
извлечённый граф C++ вызовов. Относительные пути к исходникам приведены в
описаниях элементов. Принятые решения остаются в ADR и профильных руководствах.

| Вид | Содержание |
|---|---|
| [`v_architecture`](images/semaps-architecture.png) | BtEngine, ESP-IDF backend, общий GATT, модули, экземпляры, Actions и необязательный SIG |
| [`v_data`](images/semaps-data-flow.png) | Наблюдения и CBOR → LiveViews → WS/вебка; общий журнал → LVGL; пользовательские команды → очередь |
| `v_lifecycle` | Распознавание → явное добавление → DeviceId с поколением → работа → удаление и очистка |

BtEngine владеет механизмами Bluetooth и экземплярами. Модуль определяет тип
прибора и создаёт драйвер; драйвер хранит состояние протокола и объявляет
команды/события. Приложение выбирает, когда добавлять и удалять устройства,
собирает Actions, хранит бизнес-настройки и подключает UI. Распознавание само
по себе не создаёт экземпляр. MAC с ротацией не считается вечным идентификатором.

В исследовательской демке HTTP раздаёт assets, всё состояние и управление идут
через бинарный WS/CBOR. Снимок и изменения используют один конверт. LVGL читает
те же объекты ResearchModule и MessageJournal; он не запускает второй BT стек.
Возврат из очереди в движок скрыт на `v_data` для читаемости: команды исполняет
основная задача приложения, что описано в элементах и руководстве демки.

## MCP

В репозитории находятся переносимые `.mcp.json` и `.codex/config.toml`.
Команда `semaps mcp`, запущенная из корня проекта, находит именно
`NaBTools.semaps`. Требуется установленный `semaps` в PATH. Нет машинных путей,
секретов и привязки к модели другого репозитория. Другие MCP не перенастраиваются.
Политика допуска и доверие к проекту задаются владельцем в среде запуска.

Уже открытый чат может сохранять старый процесс MCP до переподключения.
Наличие файла конфигурации само по себе не подтверждает действующее подключение:
перед работой вызвать `list_projects` и проверить id `nabtools`, затем
`graph_status`, `layout_guide` и `get_view`. Изменять модель через MCP-инструменты,
проверять `render_view`, сохранять `save` по поручению владельца, убедиться в
`unsaved=[]` и выполнить `semaps check`. Registry/view JSON вручную не редактировать.

Первичная проверка модели: три вида отрисованы через MCP, замечаний компоновки
нет; `semaps check` проходит. C++ extractor не настроен, поэтому отсутствие
extractor-facts не является доказательством полноты карты исходников.
