# Samsung SmartTag и ручное добавление

Фактическая аппаратная проверка: [отчёт C6](readme_smarttag_acceptance_ru.md).
Новый необязательный [каталог команд/событий](readme_device_interaction_ru.md)
не означает готовый GATT: кнопка и звук пока объявлены недоступными.

Новый runtime не использует старые смещения из `nabtools_samsung_EIT5300*`:
они неверны для наблюдаемого 20-байтового FD5A payload.
Разбор написан независимо по формату протокола, описанному в
[исследовании USENIX](https://www.usenix.org/system/files/usenixsecurity24-yu-tingfeng.pdf)
и проверен по [парсеру авторов исследования](https://github.com/pogen300/galaxy_smarttag_research/blob/main/other_scripts/parse_tag_ble.py).
Код сторонних проектов не скопирован. Числа/смещения — свойства протокола.

`SmartTagPacket` — проверенное заимствованное представление service data FD5A.
Для версии 1 и длины 20 байт извлекает version, advertisement type, tag state,
24-bit aging counter, 8-byte privacy ID, region, E2E/UWB, battery level 0..3,
reserved и signature. Уровень батареи — категория, не проценты.
Другие варианты FD5A сохраняются raw с decoded=false; по неизвестным данным
не придумываются поля. Короткие/битые AD и extended fragments не декодируются.
Подпись без ключа не проверяется, модель SmartTag/SmartTag+/SmartTag2 по одному
такому пакету не заявляется. Непривязанный FD59 в этот первый обработчик не входит.

`SmartTagRecognizer::matches` — простая проверка; `recognize` даёт описание
кандидата для сканера. `SmartTagModule` предоставляет фабрику `SmartTagDevice`,
но не создаёт приборы автоматически. `BtEngine::recognize` перечисляет
совпадения подключённых модулей. `attach(module_key, view, id)` повторно
проверяет пакет, обеспечивает идемпотентность и создаёт принадлежащий BT экземпляр.
Приложение исследователя выбирает пакет из ограниченного кеша наблюдений.
Возраст виден пользователю; добавление не требует, чтобы прибор постоянно
рекламировался. Если наблюдение уже вытеснено из кеша, команда вернёт expired.

В новой прошивке и TomTom переведён на ручное добавление. Страница `#devices`
заменяет TPMS-страницу; `#tpms` ведёт туда же. В эфире подходящие строки выделены
цветом и имеют название обработчика и «Добавить»; это не результат SIG lookup.
Company Samsung без FD5A не предлагается как SmartTag.

## Выход экземпляра

Один раз разобранный пакет доступен независимым STRUCT/CBOR Actions.
Нормальный CBOR контракт:
`nabtools.samsung.smarttag.advertisement.v1` в MessageInfo и карта значений с
`type=advertisement`, `change=first|payload_changed`, `decoded`, `version`,
raw и changed_offsets, а также известными полями для поддерживаемого формата.
В байтах нет зависимости от флагов компиляции потребителя.

Экземпляр считает все подходящие пакеты, но отправляет первый и изменения
service payload. Повтор рекламы и колебание RSSI не создают новые сообщения.
Список changed_offsets относится к raw service data после двух байт UUID.
При удалении экземпляра delivery прекращается; DeviceId с generation защищает
от использования старого слота после повторного добавления.

Адрес и тип адреса сейчас фиксируются при добавлении. Пассивно связывать разные
ротирующие адреса по силе сигнала или общей части пакета нельзя. Постоянная
идентичность/владельческие ключи/IRK — отдельный ещё не реализованный механизм.
Список добавленных экземпляров пока находится в RAM, не переживает перезапуск.

## Кнопка и границы проверки

В опубликованном протоколе owner-tag команды и уведомления идут через
аутентифицированный зашифрованный GATT-сеанс. В рекламе нет подтверждённого
нами универсального поля «кнопка». Изменение raw/state/signature не называется
нажатием; движения, время, подключения и ротация также могут менять рекламу.
Добавлен [исследовательский GATT слой](readme_smarttag_gatt_ru.md): подключение,
discovery, чтение информации и сырые indications. Owner-аутентификация,
расшифрованные нажатия и звук ещё не реализованы.
Для опыта фиксируем raw и время изменений до/после нажатий; результат может
быть отрицательным, что не означает неисправную кнопку.

## Прикладной транспорт и универсальная вебка

`CborAction` вынесен из TPMS в `include/NaBTools/core/action.hpp` и не требует кодека.
`integrations/research/journal.hpp` — прикладной получатель для любых модулей.
Он копирует до 16 последних сообщений, до 768 байт payload каждое, вместе с
DeviceId, временем, schema и sequence. Копии ограничены, слишком большой
payload даёт dropped; это не постоянный захват всей истории.

Исследовательский пример использует [единый поток WS/CBOR](readme_websocket_ru.md).
Начальное состояние, изменения, команды и результаты передаются через `/ws`;
HTTP обслуживает файлы интерфейса. Сообщения содержат ordinal, slot, generation,
time_ms, sequence, schema и payload как CBOR byte string. Данные обработчика
передаются без повторной сериализации MCU. Общий viewer показывает вложенные
значения и byte strings, без веток конкретных приборов. Семантические знания
остаются отдельным уровнем: см. `readme_output_levels_ru.md`.

Команда добавления:
`{add_handler:"nabtools.samsung.smarttag",address:<6 bytes>,address_type:1,sid:255,
request_id:1,boot_id:<current boot>}`.
WS ack подтверждает очередь, запись control — результат dispatch.
Создание экземпляра не имитирует новый радио-пакет: первое advertising сообщение
появляется на следующей рекламе. GATT запускается отдельной явной командой.
