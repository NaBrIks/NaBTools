# Первый исследовательский runtime

Продолжение активного слоя: [GATT и реальный пульс Garmin](readme_gatt_ru.md).
Ниже сохранено описание первого этапа; оно не отменяет новую реализацию.

23.10.2026 владелец разрешил переход к коду и прошивку подключённого C6.
Это первая экспериментальная реализация согласованного направления;
конкретные C++ API пока могут меняться по результатам использования.

## Границы и интерфейсы

ESP-IDF backend принимает `EspIdfScanTiming{interval, window}` в конструкторе.
Единица — 0,625 мс; допустимы 4..0x4000, window не больше interval.
Ошибочная конфигурация отклоняется до запуска стека. Значения по умолчанию
остаются 0x80/0x30. Равные interval/window запрашивают непрерывное сканирование,
но не отменяют арбитраж общего радио с Wi-Fi. Это механизм backend; прикладные
таймеры сеанса и выключение Wi-Fi принадлежат приложению.
`set_scan_timing()` меняет окно и интервал в контексте владельца движка:
backend ждёт завершения STOP, задаёт параметры и возобновляет прежнее намерение
сканирования после подтверждения SDK. `scan_timing()` возвращает последнюю
подтверждённую пару, а не только отправленный запрос.

API: `include/NaBTools/`, namespace `NaBTools::runtime`, C++20. Корневой CMake
подключает runtime и ESP-IDF адаптеры; PlatformIO `library.json` — переносимые
части с собственным backend. Прежняя плоская реализация удалена 29.10.2026 после
[переноса полезных возможностей](readme_retired_code_ru.md).

- `IBackend`: `start`, `pump`, `scan`, `take`, `snapshot`. SDK callback копирует
  ограниченный отчёт в очередь; движок разбирает принадлежащий ему пакет.
- `BtEngine`: владеет backend, модулями и до 32 устройств; `add_module` до старта,
  `start`, `poll`, `scan`, `add_device`, `remove_device`, `device`, `devices`.
  Все вызовы и Actions выполняются в одном контексте движка. Потокобезопасного
  вызова API из произвольной задачи нет; пример использует очередь команд.
- `IModule::observe(engine, view, status)`: получает все наблюдения, включая
  malformed/fragment; не обязан создавать прикладные экземпляры.
- `IDevice`: собственное состояние протокола и обработка подходящих пакетов.
  `DeviceId{slot,generation}` предотвращает обращение к следующему устройству
  после повторного использования слота. Удаление во время callback откладывает
  разрушение до окончания dispatch. Сырые указатели нельзя сохранять после удаления.
- `TomTomModule`: `add_known` создаёт настроенный прибор до первого пакета;
  `auto_discover` явно выбирает приложение. Исследовательский пример теперь
  выключает его: все приборы добавляются явно кнопкой из эфира.
- `TpmsActions`: независимые STRUCT/CBOR функции с пользовательским контекстом.
  `MessageInfo` передаёт устройство, время, последовательность и схему.
  Результат `Delivery` учитывает принятие/потерю. Данные заимствованы на время
  вызова: для очереди приложение делает свою копию. Контекст Action должен жить
  дольше устройства. Исключения из Actions не поддерживаются.

Приложение отвечает за настройки колёс, выбор конкретных приборов, постоянное
хранение и интеграционные Actions. BT владеет runtime экземплярами. Исчезновение
прибора из эфира само по себе не удаляет настроенный экземпляр.

## Данные и SIG

`AdvertisementView` — заимствованный пакет; `Advertisement::copy` — копия до
255 байт. Адрес включает тип. AD cursor сохраняет повторные поля, проверяет
границы. В первом backend разбираются только полные legacy отчёты. Extended
advertising сохраняется как fragment/неподдержанный для разбора: сборки цепочек
фрагментов пока нет, даже если отдельный extended отчёт помечен SDK complete.

`RadioInfo` сохраняет свойства отчёта, PHY, Tx power, periodic interval,
directed address и data status. `AdView` и `UuidListView` дают проверяемые
заимствованные обёртки без map и аллокаций; неизвестные типы доступны через raw.
Перечень SIG расширен до 15 категорий: [покрытие](readme_sig_update_ru.md).

`NABTOOLS_TPMS_STRUCT` / `NABTOOLS_TPMS_CBOR`: STRUCT, CBOR или BOTH. CBOR собирается
непосредственно из TomTom-пакета в ограниченный буфер без промежуточного DOM.
`nabtools.tpms.v1` содержит давление в Pa, signed температуру в сотых °C,
заряд, тревогу, адрес, время и sequence. CBOR writer — ограниченный definite-length
кодек для этих контрактов; универсальная CBOR библиотека из него не заявляется.

`NABTOOLS_SIG_PROFILE`: OFF=0, COMMON=1, EXTENDED=2, FULL=3; в ESP-IDF — Kconfig.
COMMON: 16 компаний, включая Samsung, Garmin и Huami, 8 сервисов, 11 характеристик.
EXTENDED: 84 компании; FULL: 4057 компаний. В EXTENDED/FULL сейчас 76 сервисов
и 512 характеристик; включены 50 AD типов. FULL означает все строки именно
поддержанных генератором таблиц, а не весь корпус SIG/GSS и полные описания.
Списки COMMON/EXTENDED курируемые, статистики «100 наиболее вероятных» нет.
OFF не содержит строк справочников. Неизвестное значение сохраняется числом/raw.

`tools/generate_sig.py` читает локальный checkout закреплённого подмодуля.
`--check` проверяет воспроизводимость. Список профилей — `tools/sig_profiles.json`.
Сетевой fetch при компиляции не выполняется. Команды и обновление —
в [руководстве SIG](readme_sig_update_ru.md).

## Исследовательское приложение

`examples/research` использует веб-сервер NaWServer. Прикладной обмен
работает через [единый WS/CBOR поток](readme_websocket_ru.md): снимок и дельты
имеют один формат. HTTP обслуживает только файлы сайта.

Наблюдения ограничены 32 строками с raw AD и именами из выбранного SIG-профиля;
старые строки вытесняются. Это не журнал всех радиопакетов. Добавление и
удаление экземпляров явные; состояние и результаты приходят через общий поток.
Детали raw/CBOR доступны по запросу. Вебка использует адаптацию TechnicalShell
и локальные Tabler Icons с сохранённой лицензией.

Wi-Fi задаётся в ignored `examples/research/main/wifi_secret.hpp` по примеру.
Без сети остаётся BLE/serial. NVS автоматически не стирается.
Сборка: `pio run -d examples/research -e c6`. Перед прошивкой следует проверить
chip, flash size и существующую таблицу разделов конкретного устройства.

## Проверки

```powershell
cmake -S . -B local/native-build -G "Visual Studio 17 2022"
cmake --build local/native-build --config Debug -j8
ctest --test-dir local/native-build -C Debug --output-on-failure
npm ci --ignore-scripts
npm test
```

20 native тестов на Windows: режимы TPMS/SmartTag/HRM, четыре SIG профиля,
parser команд, поток, GATT, взаимодействие, owner-протокол и AD/UUID обёртки.
В каждом SIG тесте дополнительно 5000 случайных входов AD. Проверяются границы,
отрицательная температура, создание/удаление и generation, прямые Actions,
malformed/fragment, ограничение таблицы. 17 Node тестов используют независимый
cborg для проверки native CBOR и совместимости браузерного кодека.
`npm run preview` открывает HTTP 127.0.0.1:5279 с тестовыми пакетами,
явно обозначенными как fixture; команд контроллера там нет.

Реальная приёмка платы и ограничения идентификации записываются отдельно в
`readme_c6_research_acceptance_ru.md`. Радиоприём производителя не доказывает
модель устройства, принадлежность владельцу или поддержку HRM/GATT.
