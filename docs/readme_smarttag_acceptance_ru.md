# Проверка SmartTag: распознавание и ограничения

На BLE-приёмнике проверен FD5A service data версии 1 длиной 20 байт.
Поддерживаемая реклама выделяется распознавателем, после явного добавления
создаётся экземпляр. Проверен цикл Add → Remove → Add: слот может переиспользоваться,
поколение изменяется, сохранённые сообщения относятся к исходному поколению.

Общий viewer показывает поля CBOR, включая raw/reserved/signature bytes,
состояние и категорию батареи. Специальной ветки Samsung в UI нет.

В эфире наблюдалась ротация адресов и privacy ID. Сходство RSSI, aging counter
или времени не доказывает принадлежность одной физической метке. Экземпляр
не объединяет адреса автоматически. Изменение рекламы не объявляется нажатием:
достоверное кнопочное событие пассивным наблюдением не установлено.

Добавлен [исследовательский GATT слой](readme_smarttag_gatt_ru.md): discovery,
чтение информации и raw-подписка. Экспериментальный [owner-слой](readme_smarttag_owner_ru.md)
реализует аутентификацию, расшифрованную кнопку и звук. На EI-T5300 проверены
получение существующего ключа, взаимная аутентификация и запуск звука,
физически подтверждённый владельцем. Реальные события кнопки и надёжная
остановка звука пока не подтверждены; тестовые соединения обрывались.
Общий GATT транспорт сам по себе эти функции не включает.
Список экземпляров и ограниченный журнал находятся в RAM.

См. [модель SmartTag](readme_smarttag_ru.md), [команды](readme_device_interaction_ru.md),
[поток WS/CBOR](readme_websocket_ru.md). Локальные захваты и идентификаторы
проверочного стенда не публикуются.
