# Исследовательский пример: NaWServer

`examples/research` использует NaWServer вместо прежнего ESP32-yaidfws.
Зависимость подключается как соседний ESP-IDF компонент `NaWServer` через
`EXTRA_COMPONENT_DIRS` и `PRIV_REQUIRES`. Для сборки разместите checkout
NaWServer рядом с NaBTools.

Канонический репозиторий — [NaBrIks/NaWServer](https://github.com/NaBrIks/NaWServer),
теперь публичный. Его текущая `main` использует TCP API. Research в этом выпуске
собирается с историческим API HTTPD. Проверенная историческая ревизия:
`0d1492f174097a0cd51ddd668b4e1029c4ce4ec9` (30.10.2026).
Она содержит обязательный `NaWServer/backends/esp_idf_request.h`.
Из общего родительского каталога:

```sh
git clone https://github.com/NaBrIks/NaWServer.git NaWServer
git -C NaWServer fetch --no-tags origin 0d1492f174097a0cd51ddd668b4e1029c4ce4ec9
git -C NaWServer checkout --detach FETCH_HEAD
```

Исторический SHA не входит в текущую ветку NaWServer. Команда fetch выше
проверена с анонимным доступом. Старый `master` с SHA
`def37759400d79453477de20e875992300617c03` не содержит request adapter и не
подходит для этого примера. Самостоятельный NaBTools smoke и native не требуют
NaWServer. Не заменяйте опубликованную зависимость незакоммиченным checkout.

Проверка 30.10.2026: чистый GitHub checkout NaBTools
`abbb3083dac724d212338b0a222de00ba3ece4ef` с прежним root NaWServer
`117fadffc62a6c8b0b2a170d0a34125883707583` прошёл
`pio run -d examples/research -e c6`. Включены BLE 5 scanning, GATT client,
HRM CBOR, COMMON SIG и HTTPD WebSocket. Размер приложения — 1 246 194 байта.
Использовались документированные подготовленные SDK/toolchains, без приватного
Wi-Fi заголовка. Это проверка сборки, а не новая аппаратная приёмка: прошивка,
COM и FS не использовались.

Исторический root `0d1492f174097a0cd51ddd668b4e1029c4ce4ec9` заменил прежний:
добавлены scoped LF attributes и уточнена документация форматирования/публикации.
C/C++ исходники, API и SDK-конфигурация не изменены; историческая проверка выше
относится к прежнему root, функциональные/SDK тесты для этой замены не повторялись.
Для этого Research используйте исторический pin из команды выше.

Заголовки имеют префикс `<NaWServer/...>`, пространство имён — `NaWServer`,
класс сервера — `NaWServer::Server`. При смене каталога зависимости очистите
старый кэш сборки PlatformIO/CMake перед повторной сборкой.

Переименование не меняет прикладной протокол: HTTP отдаёт статические файлы,
`/ws` передаёт бинарный CBOR. Начальный и восстановительный reset-снимки,
живые изменения и команды используют прежние контракты. BtEngine и модули
приборов не зависят от имени веб-сервера. Условия NaWServer определяются
LICENSE закреплённой ревизии его репозитория; переименование или перенос
NaBTools их не меняют. Указанная ревизия NaWServer использует MIT для собственного
кода и сохраняет сторонние notices. Исторически интеграция начиналась с GPL-варианта.

Проверка потребителя: собрать `examples/research` для выбранной платы,
открыть сайт, получить reset-снимок по WS, проверить рост счётчика BLE-наблюдений,
выполнить остановку/возобновление сканирования по WS и переподключить клиент.
Повторное подключение должно восстановить состояние без перезагрузки MCU.
Живые BLE-наблюдения достаточны для этой транспортной проверки; наличие
пульсометра или метки и получение их прикладных событий не требуются.

Подробности протокола: [WS/CBOR](readme_websocket_ru.md).

Проверено 23.10.2026 на ESP32-C6 после переименования в NaBTools: сборка и
загрузка приложения, открытие вебки, свежие BLE-наблюдения, бинарные CBOR дельты,
команды остановки/запуска сканирования и reset-снимок при переподключении WS.
Контроллер не перезагружался при переподключении клиента, ошибок декодирования
CBOR в контрольном сеансе не было. Прошли 20 native C++ тестов, 16 веб-тестов
и 8 Python-тестов инструмента SmartTag. Эта проверка не является повторной
приёмкой прикладных HRM/SmartTag протоколов; эксперимент с меткой остановлен.
