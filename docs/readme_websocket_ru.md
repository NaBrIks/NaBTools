# Исследовательский обмен WS/CBOR

Пример `examples/research` использует WebSocket из NaWServer. Файлы сайта
загружаются HTTP, весь прикладной обмен идёт бинарным CBOR через `/ws`:
начальная загрузка, восстановление, команды, результаты и сообщения модулей.
Периодического HTTP polling и отдельных HTTP API состояния/команд нет.

Это адаптер исследовательского приложения. BtEngine, GATT transport и драйверы
не знают о WebSocket. Протокольный модуль вызывает обычный Action; прикладной
журнал копирует payload и передаёт запись общему потоку.

## Один формат изменений

```text
{
  v: 1,
  boot_id: 42,
  seq: 100,
  reset: false,
  changes: [["message", {ordinal: 7, slot: 0, generation: 1,
    time_ms: 1234, sequence: 7, schema: "application.sample.v1",
    payload: <CBOR byte string>}]]
}
```

Обычный пакет содержит изменения. Полный снимок — тот же пакет с `reset: true`
и всеми актуальными записями. Обе формы применяет один reducer. Снимок передаётся
одним ограниченным WS-сообщением; отдельного протокола чанков нет.

| Вид записи | Содержание |
|---|---|
| runtime | Общие счётчики, состояние backend, списки актуальных ID устройств и наблюдений |
| observation | Одна строка рекламы с ключом address/address_type/sid |
| device | Один экземпляр с ключом slot/generation, командами и событиями |
| message | Неинтерпретируемый CBOR payload любого модуля и метаданные журнала |
| control | Результат dispatch, связанный с request_id |

Списки ID в runtime удаляют исчезнувшие строки. Сообщения разных поколений
не смешиваются. Журнал сохраняет последние 16 записей; это не постоянное хранилище.
Перед публикацией новой строки сервер передаёт актуальную принадлежность
коллекций: это позволяет заменить наблюдение при заполненном лимите без
временной 33-й строки и лишнего восстановления снимка.
Generic viewer разбирает произвольные CBOR поля и не содержит веток конкретных
профилей или производителей.

## Загрузка и восстановление

После upgrade сервер отправляет `hello` с v/boot_id/seq. Клиент запрашивает
`{snapshot: true}`. Пока идёт восстановление, новые изменения временно
буферизуются. Reset-пакет задаёт состояние и cursor: покрытые им события
отбрасываются, более поздний последовательный суффикс применяется дальше.

Сервер ждёт публикации снимка с cursor не старее момента запроса. Это исключает
пропуск между старым кэшированным снимком и первым изменением нового подключения.
Ожидание ограничено; при неудаче соединение закрывается для повторной загрузки.

Повторные seq игнорируются. Пропуск seq вызывает новый запрос снимка. Новый
boot_id очищает старую сессию; необработанные команды не повторяются автоматически.
Heartbeat приходит примерно раз в секунду, в том числе без измерений, чтобы
потеря последнего события не оставалась незамеченной. При разрыве клиент повторяет
подключение с задержкой 0,5–5 секунд и снова загружает снимок.

## Команды

Запросы передаются CBOR map в том же WS. Примеры:

```text
{snapshot: true}
{scan: true, request_id: 10, boot_id: 42}
{remove_slot: 0, generation: 1, request_id: 11, boot_id: 42}
{invoke_slot: 0, generation: 1, invoke: "connection.connect",
 arguments: <CBOR byte string>, request_id: 12, boot_id: 42}
```

`ack/status=queued` подтверждает постановку в очередь. Запись control сообщает
результат dispatch; последующие сообщения драйвера описывают реальное выполнение
протокола. Старый boot_id отвергается как expired до очереди. Формат и доступность
команды проверяет соответствующий модуль; UI использует объявленные каталоги.

## Границы ресурсов

Обычный пакет до 4 KiB, reset-снимок до 32 KiB, запрос до 192 байт. Два
фиксированных буфера снимков позволяют держать опубликованный пакет во время
передачи и продолжать работу BT. При отсутствии свободного буфера сохраняется
предыдущий полный пакет; частичный снимок не публикуется.

Задача BT не отправляет данные в сеть: она копирует готовый пакет в очередь
из четырёх элементов без ожидания. Отдельный worker пользуется ограниченной
очередью NaWServer. Не более двух WS-клиентов. Счётчик seq увеличивается
и при отказе очереди: следующий пакет выявит пропуск, после чего клиент
восстановится. Счётчики dropped передаются в runtime. Медленный клиент не
получает неограниченную очередь.

Обновления рекламы и состояния таблиц объединяются; проверяется по одной строке
каждой ограниченной коллекции за шаг. Сообщения модулей и control ставятся
в очередь сразу, без ожидания периодического обновления таблицы. Во время
передачи полного снимка coalesced view updates приостановлены; сообщения модулей
продолжают учитываться. Доставка сети не означает гарантированный журнал:
при потере связь восстанавливается из текущего состояния и ограниченной истории.

## Проверки

Native tests проверяют владение bytes, callback журнала, переполнение и видимые
пропуски. Web tests используют независимый CBOR codec и проверяют единый reducer,
cursor cutover, дубликаты, gaps, reboot, ограниченные буферы и команды через WS.
`npm run preview` запускает явно помеченные синтетические данные с тем же протоколом.
Успешные native проверки не заменяют аппаратную проверку радиоканала и сети.

В NANO таблицы имеют минимальные вертикальные отступы и компактные кнопки.
Пункты меню не меняют начертание при выборе; длинные подписи не переносят строки.
Значок Bluetooth — Tabler SVG с сохранённой MIT-лицензией в `examples/research/web/icons/`.

Таблицы обновляются по ключам строк и полей. Неизменившиеся DOM-узлы и кнопки
сохраняются; обновляется только изменившийся текст. Во время выделения текста
соответствующая таблица сохраняет показанное состояние до снятия выделения.
Открытый выбор сообщения CBOR также не перестраивается обновлениями потока.
Эти локальные паузы представления не останавливают приём WS и состояние модели.
