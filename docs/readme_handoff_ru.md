`Readme.ru.md` — русский: зависимости, чистая сборка и ограничения согласованы.
Исходники классификатора, CMake-список и ESP-IDF ScanMode/ScanTiming опубликованы
в `9ff6b878f80227f7c4da47fc3caefa71c1c68791`; последующие изменения документации
могут иметь новую SHA. Потребитель должен закреплять фактически выбранную полную SHA.

На удалённой ревизии проверяются native/CBOR, browser tests и link-only ESP-IDF
smoke. Используется подготовленная SDK из документированного окружения; это не
проверка установки toolchain с нуля. Исследовательский пример дополнительно
требует отдельный NaWServer; его чистую публикацию и API нельзя подменять
неопубликованными изменениями соседнего checkout.

Опубликованные этапы: MIT/исключения — `5339f3ed4631b17b39d6419a524827bc1ca9ceb6`,
общий Uncrustify 0.83.0_f — `abbb3083dac724d212338b0a222de00ba3ece4ef`.
Из GitHub checkout последнего прошли 22 native-теста, 21 web-тест и C6 research
с опубликованным NaWServer `117fadffc62a6c8b0b2a170d0a34125883707583`.
Это историческая проверка прежнего root; текущий pin и инструкция закрепления
зависимости — [NaWServer](readme_nawserver_ru.md).
Повторная проверка форматирования чистая; данные SIG/vendor не форматировались.
Отдельно прошли 12 Python-тестов и проверка генератора SIG, сборки S3 smoke и
research LCD7. Радио/LVGL в этой проверке на железе не запускались.

Тайминги теперь имеют fake-SDK покрытие реального backend, включая асинхронное
применение и отказ. Приватные credentials/журналы/бинарники не включаются в Git.
Платы и FS при публикации не менялись. Владелец 30.10.2026 явно выбрал MIT для
своего кода; исходники получили SPDX/copyright, strict JSON — только metadata.
Условия адаптера LCD7, SIG и иконок сохранены. Аудит не делает вывод о чужом
авторстве только по прежнему GPL LICENSE, см. [границы](third_party.md).

## Классификация рекламы и ScanMode, 29.10.2026

Добавлены переносимый `classify_advertisement`, типы/возможности с основаниями
и различением предположений по имени. Вебка показывает три отдельные сортируемые
колонки. ResearchModule объединяет недавние факты advertising/scan response
одного адреса, не создавая устройства и не подключаясь. Модули могут указать
`Detection::kind`, generic engine не знает vendor-протоколов.

`BtEngine::set_scan_mode` и ESP-IDF backend поддерживают passive/active,
WS/CBOR команда — `scan_mode`. Применение асинхронное, с сохранением паузы и
отдельным фактическим/запрошенным состоянием. Аппаратная проверка active scan
не выполнялась; проверка ограничена тестами и сборками. [API, правила и проверки](readme_advertising_classification_ru.md).

## Единственный runtime, 29.10.2026

По поручению владельца полезные оставшиеся обёртки и SIG-категории перенесены,
а 49 файлов плоской реализации, дублей, старых генераторов и заметок удалены.
Версия — 0.3.0, C++20, без nlohmann-json и авторегистрации. Публичный API:
`NaBTools::runtime`; компоненты собираются из feature-папок. В `AdView` есть
заимствованные AD/UUID helpers, в `RadioInfo` — факты GAP-отчёта; CBOR и экран
видят метаданные радио. Все прежние категории SIG входят в единый optional
каталог, включая добавленный appearance.

[Аудит переноса](readme_retired_code_ru.md) содержит соответствия API,
проверки и оставшиеся ограничения. [ADR](adr/ADR_20261029_single_runtime.md)
заменяет временное сохранение исходной реализации. Архивные отчёты и
манифест выделения не являются актуальным перечнем файлов или зависимостей.

## Экран S3, 28.10.2026

Основная research-демка получила необязательный профиль `s3_lcd7` для
Waveshare ESP32-S3-Touch-LCD-7 Rev1.2. Реализация и зависимости локализованы в
[display/research_lcd7](../examples/research/display/research_lcd7/README.md);
обычный C6 остаётся без LVGL. Это новый потребитель BtEngine/ResearchModule
и общего журнала, а не восстановление удалённого BLE/LVGL legacy-примера.
Экран не инициализирует второй Bluetooth стек.

Есть эфир с названными AD-полями/raw, явное добавление, экземпляры с generic
командами модулей и просмотр полученного CBOR. UI и работа движка сериализованы
в задаче приложения. На компьютере проверены выбор, очередь add/scan/remove,
устаревшее поколение экземпляра, вытеснение сообщений и LVGL-отрисовка.
После разрешённой прошивки на S3 подтверждены сканирование, HTTP assets,
живые WS/CBOR изменения, reset-снимок и восстановление соединения; команды
Pause/Start работают через общий транспорт. Счётчик RGB кадров растёт,
GT911 инициализирован, ошибок опроса нет. Физический вид панели и касание
пальцем требуют визуальной приёмки. На компьютере прошли 20 native,
17 web и один тест настоящего LVGL. Для браузерных таймеров watchdog/reconnect
исправлен вызов с неверным receiver; отдельный тест воспроизводит это ограничение.

Для совместной нагрузки уменьшены внутренние RGB/Wi-Fi буферы и включены
PSRAM-first/dynamic allocations Bluedroid. Это настройки экранной демки.
Без них наблюдалась нехватка внутренней DMA-памяти при запуске Wi-Fi.

Добавлена [карта SeMaps](readme_semaps_ru.md): компоненты, данные и жизненный
цикл устройств. MCP запускается из корня NaBTools и проверяет id `nabtools`.

Для обновлённого NaWServer HTTPD/ESP-IDF 5.5.6 в research defaults включён
`HTTPD_WS_POST_HANDSHAKE_CB_SUPPORT`. Это требование native WebSocket backend;
переход на другой backend этой работой не выполнялся.

## Библиотека и веб-исследователь

NaBTools содержит экспериментальный BtEngine с модулями, BT-owned экземплярами,
явным добавлением/удалением, независимыми STRUCT/CBOR Actions и отключаемым SIG.
Backend ESP-IDF предоставляет общий GATT client; Heart Rate реализован отдельным
стандартным профилем. Получение реальных уведомлений проверено на ESP32-C6.

Исследовательская вебка использует единый поток WS/CBOR: полный снимок и изменения
имеют один формат. При пропуске последовательности запрашивается reset-снимок.
HTTP обслуживает статические файлы. UI выводит произвольные CBOR поля и
объявленные модулем команды/события.

Начать с [архитектуры](adr/ADR_20261023_bt-engine-modules.md),
[структуры файлов](readme_layout_ru.md), [GATT](readme_gatt_ru.md),
[WS/CBOR](readme_websocket_ru.md), [уровней outputs](readme_output_levels_ru.md).
Подробные предложения API остаются предложениями, а текущий runtime не является
стабильным публичным ABI. SmartTag получил исследовательский GATT слой:
[реализация и границы](readme_smarttag_gatt_ru.md). Pairing/security,
Owner-аутентификация SmartTag, зашифрованные команды звука и события кнопки
реализованы экспериментально в Samsung-модуле; см. [ключ и протокол](readme_smarttag_owner_ru.md).
На EI-T5300 подтверждены получение ключа через Devices API, owner-аутентификация
и запуск звука. Встречный proof этой метки содержит завершающий NUL; проверяются
два точных варианта блока. Реальные кнопочные события и надёжный Stop sound
ещё не подтверждены из-за обрывов тестовых соединений. Аудио ещё впереди.

Публичная документация описывает библиотеку и воспроизводимые примеры.
Сведения о конкретном рабочем месте, устройствах и локальной сети в неё не включаются.

Текущие примеры используют [общую ESP-IDF 5.5.6](readme_shared_idf_ru.md); прежние SDK-пины из отчётов не применять.

[Рекомендуемая структура и версии окружения](readme_development_environment_ru.md) — базовый вариант для воспроизведения, не обязательное ограничение.
