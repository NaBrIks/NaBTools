# SmartTag через общий GATT

Активная исследовательская часть модуля находится в
`src/devices/samsung/smarttag/gatt.cpp`. Движок и ESP-IDF backend содержат только
общие механизмы GATT; UUID, имена и ограничения SmartTag остаются в модуле.

Реализованы явные Connect/Disconnect, discovery всех сервисов, чтение известных
незашифрованных model/firmware/cipher и диагностическая подписка на характеристику
кнопки. Discovery выводит UUID, handles, parent handles и свойства, включая
неизвестные элементы. Наличие UUID не доказывает аутентичность метки.
При подключённом SIG стандартные сервисы и характеристики получают его имена;
без SIG специфичные имена модуля и исходные UUID сохраняются.

Выходы независимы: STRUCT callback `SmartTagActions::gatt` получает borrowed
`SmartTagGattReading`; CBOR Action получает `nabtools.samsung.smarttag.gatt.v1`.
Последний включает event/state/status/error, field/uuid/handles, request_id и raw.
Приложение копирует данные при асинхронной передаче. Общий viewer не знает
Samsung и показывает эти поля обычным способом.

## Ограничение кнопки и звука

Исследованный owner-протокол использует взаимную аутентификацию, nonce,
сессионный ключ, AES-CBC/PKCS7 и счётчик команд. GATT connect, BLE pairing и
owner-аутентификация — разные операции. Ключ владельца нельзя восстановить из
MAC или открытой рекламы.

`button.observe_raw` подписывается на найденную характеристику, если она и CCCD
доступны. Полученные bytes имеют тип `button.raw`, `authenticated=false` и
`button_decoded=false`. Зашифрованный пакет или изменение рекламы не объявляются
нажатием. Успешная подписка сама по себе не обещает получения indications.

Экспериментальный owner-слой описан отдельно: [ключ владельца и протокол](readme_smarttag_owner_ru.md).
`owner.authenticate` использует application provider ключа и crypto-адаптер.
После взаимной проверки доступны `alert.start`/`alert.stop` и `button.observe`.
Без provider или успешной аутентификации эти команды не исполняются; причины
видны в общем каталоге операций. Owner-аутентификация и запуск звука проверены
на EI-T5300; реальные кнопочные события и надёжный Stop ещё проверяются.

Получение ключа существующей регистрации проверяется через Devices API;
его выдача конкретному аккаунту/токену не гарантирована. Хранение/предоставление credentials
принадлежит приложению; протокол аутентификации и преобразование сообщений —
модулю. Секреты не относятся к исследовательскому журналу и публичным fixtures.
Устойчивое сопоставление ротирующихся адресов также требует отдельного механизма;
совпадение RSSI не является таким механизмом.

Источники формата: [исследование, приложение C](https://arxiv.org/pdf/2210.14702),
[артефакты авторов: описание команд](https://github.com/pogen300/galaxy_smarttag_research/tree/main/investigation/web_traffic_analysis/command_set).
Они описывают определённые версии SmartTag, а не универсальную спецификацию
всех поколений. Код написан отдельно по описаниям протокола.

Native test проверяет маршрутизацию по session/generation, discovery, чтение,
подписку, сохранение raw и удаление из Action. Эти проверки не заменяют
аппаратного подтверждения звука или нажатий.
