# Единая реализация и удаление старого кода, 29.10.2026

По решению владельца полезные оставшиеся возможности исходной библиотеки
перенесены в модульный runtime. Отдельной поддерживаемой старой реализации
больше нет. Версия библиотеки — 0.3.0; это изменение исходного API.
Решение закреплено в [ADR](adr/ADR_20261029_single_runtime.md).

## Что перенесено

| Возможность исходного кода | Текущий интерфейс |
|---|---|
| Разбор и просмотр полей advertising | `bt/gap/ad_view.hpp`: `AdView`, `AdCursor`, заимствованные span/string_view |
| Списки UUID и service data 16/32/128 bit | `UuidListView`, `Uuid::from_wire`, `AdView::service_data`; порядок байт Bluetooth |
| Flags, имя, Tx power, appearance, role, class, OOB/TK, интервалы | Проверяемые optional-getters `AdView`; диапазон connection interval читает четыре байта |
| Поля SDK-отчёта | `AdvertisementView`/`Advertisement::radio`: `RadioInfo` с PHY, свойствами, Tx power, periodic interval, directed address и data status |
| Копирование для очереди и сравнение | Владеющий `Advertisement::copy`, типизированный `Address`, `Uuid`; метаданные копируются вместе с пакетом |
| Имена AD/компаний и все прежние UUID-таблицы | Один `catalogs/sig`, 15 категорий с appearance, OFF/COMMON/EXTENDED/FULL |
| Единицы давления/температуры | `core/units.hpp`: SI-значение и вычисляемые преобразования; `TpmsReading::pressure/temperature` |
| TomTom TPMS | `devices/tomtom/tpms`: модуль, экземпляры, независимые STRUCT/CBOR Actions |
| Исследование Samsung | `devices/samsung/smarttag`: распознавание, экземпляры и экспериментальный owner/GATT протокол |
| Исследовательские принты и разбор | `ResearchModule`, именованные/raw CBOR-наблюдения, вебка и необязательный LCD пример |

Getters заимствуют байты исходного пакета и не продлевают его жизнь. Для
асинхронной обработки нужна владеющая копия. Численные unknown-значения не
теряются при отсутствии имени в SIG. SDK-специфичные типы остаются в backend.

Перенос сохраняет полезные механизмы, а не прежние сигнатуры и формат принтов.
Потребителям плоских заголовков нужны новые include, явная композиция движка
и Actions. Автоматической миграции внешних приложений эта работа не выполняет.

## Что удалено

Удалены 49 файлов: 12 плоских `src/NaBTools*`, `src/njsonex.hpp`,
28 файлов дублирующих производных SIG, 5 старых Python-генераторов/шаблонов,
2 заметки Doc/ и тест прежнего SIG API. Вместе с ними ушли singleton
`BTController`, статическая авторегистрация, тестовый MAC-распознаватель,
weak CBOR loop/events, PMR-эксперимент и требование C++23 для `join_with`.
Зависимости от nlohmann-json больше нет.

Корневые CMake и `library.json` используют единственный runtime. ESP-IDF smoke
переведён на настоящий компонент и новые заголовки; радио он не запускает.
История удалённых файлов доступна в Git, папка с их копией не сохраняется.

## Что осталось от предыдущих этапов

- `bluetooth-SIG/` — необязательный подмодуль и источник локальной генерации.
  Его ревизия закреплена в Git. Условия и notices находятся в upstream.
- Датированные ADR, отчёты выделения/приёмки, ранние предложения интерфейсов и
  `extraction-source-manifest.json` — история решений. Манифест содержит пути
  уже удалённых файлов и не является текущим перечнем исходников. Исторические
  отчёты помечены; действующие инструкции находятся в README и handoff.
- Короткие `include/NaBTools/*.hpp` и
  `integrations/espidf/NaBTools_espidf.hpp` — заголовки-перенаправления на
  канонические feature-пути. Дублирующих классов/реализаций в них нет.
- Экспериментальный Samsung-модуль оставлен по прямому решению владельца.
  Его незавершённая аппаратная проверка не означает наличие старого runtime.

## Текущие ограничения

Это оставшаяся работа, а не причины держать удалённый код:

- Extended advertising пока не собирается из фрагментов. Runtime считает такой
  отчёт fragment даже при SDK data status Complete. Сырые данные доступны.
- Владеющий пакет ограничен 255 байтами; очередь, таблица наблюдений, журнал
  и CBOR-буферы ограничены. Это не неограниченный Bluetooth sniffer; тяжёлый
  снимок или переполнение требуют учёта отказа/потерь в приложении.
- SIG даёт имена назначенных номеров. Полные GSS-описания полей, единиц и
  значений всех сервисов ещё не превращены в модель знаний. Названия SDP/Classic
  не означают реализацию этих транспортов, аудио или полного Mesh стека.
- Identity при ротации адресов требует подтверждённого протокольного признака
  или механизма стека. Похожее advertising не доказывает тождество устройства.
- SmartTag: ранее проверены owner-аутентификация и запуск звука, но реальные
  события кнопки и надёжный Stop sound аппаратно не подтверждены.
- API экспериментальный. Проверки на Windows и ESP-IDF не заменяют проверку
  других компиляторов, длительной нагрузки и физического поведения устройств.

## Проверки этого переноса

- 20 native тестов: AD/UUID, владение и метаданные, malformed/fragment,
  SIG OFF/COMMON/EXTENDED/FULL, GATT, lifecycle и выходы модулей.
- 17 веб-тестов: независимое декодирование CBOR, поток и DOM; новые radio-поля
  проверяются в бинарном fixture, отсутствие метаданных передаётся как null.
- Headless-тест с настоящим LVGL: отрисовка и очередь команд исследовательского
  экрана. Это не физическая приёмка дисплея.
- Успешные ESP-IDF сборки: S3 smoke, C6 research, S3 LCD7 research.
- Детерминированная регенерация SIG (`python tools/generate_sig.py --check`).
- 4 offline Python-теста входных таблиц: контекстные имена AD, дубликаты и
  диапазоны UUID, категории/subcategory appearance. Карта SeMaps проходит check.

Эти проверки выполнены без перепрошивки плат и без обновления upstream SIG.
Локальные build logs и бинарные артефакты не публикуются.
